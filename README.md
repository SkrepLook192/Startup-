## 1. Цель практической работы

Цель практического занятия №32 — подготовить демонстрируемую версию стартап-продукта и оформить комплект инженерно-продуктовой документации для проверки ключевого пользовательского сценария.

В рамках работы по проекту **Hobby Worlds** необходимо показать, что продукт уже можно запустить, пройти основной сценарий и получить понятный результат: пользователь входит в приложение, выбирает мир, работает с хобби-целями, видит прогресс, публикует результат в ленту и может взаимодействовать с другими пользователями.

---

## 2. Краткое описание продукта

**Hobby Worlds** — приложение для людей, которые хотят заниматься хобби регулярно, но часто откладывают это из-за нехватки мотивации, структуры и окружения.

Приложение объединяет несколько механик:

- личный профиль пользователя;
- выбор тематического мира;
- цели и задания по хобби;
- прогресс и опыт;
- социальную ленту;
- посты с фото/видео;
- лайки, репосты и комментарии в рамках социальной механики;
- друзей и личные сообщения;
- публичные профили других пользователей;
- визуальный игровой мир как главную фишку продукта.

Главная идея продукта: **хобби должно ощущаться не как скучная обязанность, а как развитие собственного мира**.

## 3. Текущая стадия проекта

Проект находится на стадии **демоверсии MVP**.

На текущем этапе уже реализуются ключевые продуктовые блоки:

| Направление | Состояние |
|---|---|
| Регистрация и вход | Реализовано на уровне MVP |
| Профиль пользователя | Реализован, дорабатывается визуальная часть |
| Светлая и тёмная тема | Реализована, требуется полная унификация всех экранов |
| Лента постов | Реализована, требуется стабильная загрузка только реальных постов |
| Создание поста | Реализовано, включая медиа |
| Лайки и репосты | Реализуются и тестируются |
| Сообщения | Реализованы, требуется улучшение UX |
| Друзья | Реализованы, требуется доработка отображения связей |
| Публичный профиль | Реализуется под стиль основного профиля |
| Мир | Базовый экран есть, требуется развитие как главной фишки продукта |

## 4. Scope демоверсии

Для практики №32 фиксируется функциональный скоуп демоверсии, чтобы не раздувать проект и сосредоточиться на основном пользовательском сценарии.

### 4.1. Must have — ядро демоверсии

| № | Требование | Почему важно |
|---:|---|---|
| 1 | Пользователь может зарегистрироваться или войти в аккаунт | Без авторизации невозможно сохранить персональный прогресс |
| 2 | Пользователь может выбрать тематический мир | Мир является главной фишкой проекта |
| 3 | Пользователь видит свой профиль | Профиль фиксирует личность, прогресс и публикации |
| 4 | Пользователь может создать пост | Пост показывает результат занятия хобби |
| 5 | Пост отображается в реальной ленте | Лента подтверждает социальную ценность продукта |
| 6 | Можно поставить лайк посту | Лайки дают быструю обратную связь |
| 7 | Можно поделиться постом в сообщениях | Репост связывает ленту и коммуникации |
| 8 | Пользователь может открыть чат с другом | Общение поддерживает мотивацию |
| 9 | Можно открыть публичный профиль другого пользователя | Нужна социальная навигация между людьми |
| 10 | Экран мира открывается после выбора мира | Пользователь должен видеть главный игровой результат |

### 4.2. Should have — желательно для демо

| № | Требование | Польза |
|---:|---|---|
| 1 | Переключение светлой и тёмной темы | Улучшает персонализацию интерфейса |
| 2 | Адаптация чата под тему | Делает сообщения читаемыми в любом режиме |
| 3 | Отображение друзей чужого профиля | Улучшает социальный сценарий |
| 4 | Поиск друзей при создании нового сообщения | Ускоряет начало общения |
| 5 | Редактирование собственного поста | Делает ленту полноценнее |
| 6 | Красивый glass-эффект в нижнем баре | Поддерживает фирменный стиль приложения |

### 4.3. Could have — переносится на следующую итерацию

| № | Требование | Причина переноса |
|---:|---|---|
| 1 | Полноценный 3D-мир с островами и домами | Требует отдельного этапа проектирования и оптимизации |
| 2 | Система строительства объектов в мире | Нужна отдельная игровая логика |
| 3 | Глубокая система достижений | Требуется проработка баланса и правил |
| 4 | Рекомендации друзей по интересам | Требуется аналитика интересов |
| 5 | Глобальный рейтинг пользователей | Не критично для первого демо |
| 6 | Монетизация и магазин предметов | Не входит в MVP-демо |

## 5. Definition of Done демоверсии

Демоверсия считается готовой, если выполнены следующие критерии:

- [x] Пользователь может запустить приложение.
- [x] Пользователь может пройти регистрацию или вход.
- [x] После входа пользователь попадает в основной интерфейс.
- [x] Пользователь может выбрать или открыть мир.
- [x] В приложении есть нижняя навигация: мир, лента, профиль.
- [x] Пользователь может открыть свой профиль.
- [x] Пользователь может создать пост.
- [x] Пост сохраняется и появляется в ленте.
- [x] В ленте отображаются реальные посты, а не моковые данные.
- [x] Пользователь может поставить лайк.
- [x] Пользователь может поделиться постом в чат.
- [x] Пользователь может открыть сообщения.
- [x] Пользователь может перейти в профиль собеседника.
- [x] Реализованы пустые состояния и сообщения об ошибках.
- [x] Подготовлены инструкция запуска, демо-скрипт и чек-лист тестирования.

## 6. Основной end-to-end сценарий

### Сценарий: пользователь начинает развивать хобби и делится результатом

| Шаг | Действие пользователя | Ожидаемый результат |
|---:|---|---|
| 1 | Пользователь открывает приложение | Отображается экран входа или регистрации |
| 2 | Пользователь входит в аккаунт | Открывается основной интерфейс приложения |
| 3 | Пользователь выбирает или открывает свой мир | Отображается экран мира |
| 4 | Пользователь переходит в ленту | Открывается вкладка социальной ленты |
| 5 | Пользователь нажимает кнопку создания поста | Открывается экран создания публикации |
| 6 | Пользователь вводит текст и добавляет медиа | Медиа отображается в превью |
| 7 | Пользователь публикует пост | Пост сохраняется на сервере |
| 8 | Пользователь возвращается в ленту | Новый пост отображается в ленте |
| 9 | Другой пользователь ставит лайк или пользователь проверяет лайк | Счётчик лайков обновляется |
| 10 | Пользователь делится постом в сообщениях | В чате появляется карточка репоста |
| 11 | Собеседник открывает профиль автора | Открывается публичный профиль |
| 12 | Пользователь возвращается в мир | Прогресс и игровые действия связаны с общей мотивацией |

**Фиксируемый результат:** пользователь смог выполнить действие по хобби, создать публикацию, получить социальную реакцию и вернуться к развитию своего мира.

## 7. Альтернативный сценарий

### Сценарий: пользователь пытается создать пост без текста и медиа

| Шаг | Действие | Реакция системы |
|---:|---|---|
| 1 | Пользователь открывает ленту | Лента загружается |
| 2 | Пользователь нажимает `+` | Открывается экран создания поста |
| 3 | Пользователь не вводит текст | Поле остаётся пустым |
| 4 | Пользователь не добавляет медиа | Превью отсутствует |
| 5 | Пользователь нажимает «Опубликовать» | Система показывает ошибку |
| 6 | Пользователь добавляет текст | Кнопка публикации становится доступной |
| 7 | Пользователь публикует пост | Пост появляется в ленте |

**Цель альтернативного сценария:** проверить, что приложение не создаёт пустые публикации и помогает пользователю исправить ошибку.

## 11. Контракт логики и API

| Направление | Endpoint / метод | Назначение |
|---|---|---|
| Auth | `POST /auth/register` | Регистрация пользователя |

## 13. Протокол первого end-to-end прогона

| Проверка | Результат | Проблема | Решение |
|---|---|---|---|
| Вход в приложение | Успешно | Нет | Оставить |
| Открытие профиля | Частично успешно | Профиль иногда долго загружается | Добавить обработку loading/error |
| Открытие ленты | Частично успешно | Могли появляться тестовые посты | Убрать fallback и фильтровать fake/demo данные |
| Создание поста | Успешно | Медиа не всегда сразу отображалось | Поддержать разные форматы media |
| Лайк поста | Частично успешно | Не всегда видно изменение лайка | Сделать optimistic update |
| Репост в чат | Частично успешно | Серый текст плохо читался в тёмной теме | Усилить контраст карточки репоста |
| Переход в профиль собеседника | Успешно | Нет | Оставить |
| Открытие мира | Частично успешно | Тема не всегда применялась | Перевести экран мира на общий theme context |

## 19. Ограничения текущей версии

На текущем этапе демоверсия не является финальным продуктом. Ограничения:

- 3D-мир пока реализован как базовый экран, а не как полноценная интерактивная карта.
- Система строительства требует отдельной игровой логики.
- Достижения пока нуждаются в более глубокой системе условий.
- Не все ошибки backend могут быть обработаны идеально.
- Необходимо дополнительно проверить приложение на разных размерах экранов.
- Требуется финальная оптимизация под iOS и Android.
- Монетизация, магазин предметов и партнёрские механики не входят в текущую демоверсию.
