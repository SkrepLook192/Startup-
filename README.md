## 1. Краткое описание проекта

**Hobby Worlds** — мобильное приложение для развития хобби через игровые задания, социальную ленту, друзей, сообщения, достижения и персональный 3D/визуальный мир пользователя.

Идея проекта заключается в том, чтобы превратить регулярное занятие хобби в понятный игровой процесс. Пользователь выбирает интересующее направление, получает задания, выполняет их, публикует прогресс, общается с другими людьми и постепенно развивает свой личный мир.

### Основная проблема пользователя

Многие люди хотят заниматься хобби, но часто откладывают его из-за отсутствия структуры, мотивации, компании и видимого прогресса. Приложение помогает убрать этот барьер за счёт игровых механик, социальной поддержки и понятного пути развития.

### Ценность продукта

Пользователь получает не просто список задач, а живую систему развития:

- личный профиль и прогресс;
- задания по хобби;
- публикации и ленту;
- друзей и личные сообщения;
- достижения;
- визуальный мир, который развивается вместе с активностью пользователя.

## 2. Цель практической работы

Цель практической работы — перейти от идеи, гипотез, MVP-скоупа и предыдущего продуктового плана к демонстрируемой версии решения.

В рамках практики необходимо показать, что продукт можно не только описать, но и реализовать в виде работающей демоверсии, где пользователь проходит ключевой сценарий от входа в приложение до получения результата.

Для проекта **Hobby Worlds** в качестве демонстрационного результата рассматривается мобильная версия приложения, где пользователь может:

1. зарегистрироваться или войти в аккаунт;
2. выбрать мир;
3. попасть в основной интерфейс;
4. перейти в мир, ленту или профиль;
5. создать пост;
6. увидеть пост в ленте и профиле;
7. взаимодействовать с другими пользователями через друзей и сообщения.

## 3. Scope разработки демоверсии

Для ограничения объёма разработки функции были разделены по приоритетам: **Must**, **Should** и **Could**.

### 3.1. Must-have функции

| № | Функция | Почему входит в ядро |
|---|---------|----------------------|
| 1 | Регистрация и вход пользователя | Без авторизации невозможно привязать профиль, посты и прогресс к конкретному пользователю |
| 2 | Выбор мира при первом входе | Мир является одной из главных фишек приложения |
| 3 | Главная навигация: Мир / Лента / Профиль | Пользователь должен быстро переходить между основными разделами |
| 4 | Профиль пользователя | Нужен для отображения личности, публикаций, друзей и прогресса |
| 5 | Лента постов | Основной социальный раздел, где пользователь видит активность других |
| 6 | Создание поста | Ключевое действие для демонстрации прогресса в хобби |
| 7 | Отображение постов в ленте и профиле | Пользователь должен видеть результат своего действия |
| 8 | Друзья и переход в чужой профиль | Нужны для социального взаимодействия |
| 9 | Личные сообщения | Позволяют пользователям общаться и делиться постами |
| 10 | Адаптация под светлую и тёмную тему | Важна для целостности интерфейса и пользовательского опыта |

### 3.2. Should-have функции

| № | Функция | Обоснование |
|---|---------|-------------|
| 1 | Лайки постов | Повышают вовлечённость и дают социальную обратную связь |
| 2 | Репост/поделиться постом | Расширяет социальное взаимодействие |
| 3 | Редактирование и удаление своих постов | Делает пользовательский контроль над контентом полноценнее |
| 4 | Жалоба на чужой пост | Минимальный элемент безопасности и модерации |
| 5 | Поиск друзей при создании диалога | Упрощает старт общения |
| 6 | Анимации и улучшенный glass-интерфейс | Повышают качество демо и визуальную привлекательность |

### 3.3. Could-have функции

| № | Функция | Почему перенесена дальше |
|---|---------|--------------------------|
| 1 | Полноценный 3D-мир с островами и домами | Сложная разработка, требует отдельного этапа |
| 2 | Глубокая система строительства | Нужна после стабилизации базового мира |
| 3 | Продвинутая система достижений | Можно развивать после рабочего core-сценария |
| 4 | Рейтинг пользователей | Не критично для первой демоверсии |
| 5 | Push-уведомления | Полезно, но не обязательно для первого end-to-end сценария |
| 6 | Система рекомендаций друзей и хобби | Требует накопления пользовательских данных |

## 4. Definition of Done демоверсии

Демоверсия считается готовой, если выполнены следующие критерии:

1. Пользователь может зарегистрироваться или войти в приложение.
2. После входа пользователь может выбрать мир.
3. Пользователь попадает в основной интерфейс приложения.
4. Работают основные вкладки: **Мир**, **Лента**, **Профиль**.
5. Профиль пользователя загружается без критических ошибок.
6. В профиле отображаются логин, аватар, количество друзей и публикаций.
7. Пользователь может создать пост.
8. Созданный пост отображается в ленте.
9. Созданный пост отображается в профиле пользователя.
10. Пользователь может поставить лайк посту.
11. Пользователь может открыть сообщения.
12. Пользователь может перейти в профиль другого человека.
13. Интерфейс адаптируется под светлую и тёмную тему.
14. Есть обработка пустых состояний: нет постов, нет друзей, нет сообщений.
15. Есть минимальная обработка ошибок API и загрузки данных.
16. Подготовлена инструкция запуска проекта.
17. Подготовлен чек-лист тестирования.
18. Зафиксированы ограничения текущей версии.
19. Подготовлен backlog следующей итерации.
20. Демоверсию можно показать преподавателю или пользователю без ручного объяснения каждого действия.

## 5. Основной end-to-end сценарий

### Сценарий: пользователь начинает пользоваться Hobby Worlds и публикует первый прогресс

| Шаг | Действие пользователя | Ожидаемый результат |
|-----|------------------------|---------------------|
| 1 | Пользователь открывает приложение | Отображается экран входа/регистрации |
| 2 | Пользователь регистрируется или входит | Приложение проверяет данные и создаёт сессию |
| 3 | Пользователь выбирает мир | Выбранный мир сохраняется за пользователем |
| 4 | Пользователь попадает на основной экран | Открывается нижняя навигация с разделами Мир / Лента / Профиль |
| 5 | Пользователь переходит в профиль | Видит логин, аватар, друзей, публикации и вкладки |
| 6 | Пользователь нажимает кнопку добавления поста | Открывается экран создания публикации |
| 7 | Пользователь вводит текст и добавляет медиа | Данные отображаются в форме создания поста |
| 8 | Пользователь публикует пост | Пост сохраняется через API |
| 9 | Пользователь открывает ленту | Новый пост отображается в списке публикаций |
| 10 | Пользователь ставит лайк | Счётчик лайков обновляется визуально |
| 11 | Пользователь открывает сообщения | Видит список чатов или друзей для начала общения |
| 12 | Пользователь открывает профиль другого человека | Отображается публичный профиль пользователя |
| 13 | Пользователь возвращается в мир | Видит основной раздел прогресса и игровые функции |

### Фиксируемый результат

Пользователь прошёл базовый сценарий: вошёл в приложение, выбрал мир, создал пост, увидел его в ленте и профиле, а также смог перейти к социальному взаимодействию.

## 10. Контракт логики и API

Проект реализуется как мобильное приложение на **React Native / Expo** с backend на **Node.js / Express** и базой данных **MySQL**.

### Основные группы API

| Направление | Пример endpoint | Назначение |
|------------|-----------------|------------|
| Auth | `POST /auth/register` | Регистрация пользователя |
| Auth | `POST /auth/login` | Вход пользователя |
| Profile | `GET /profile/me` | Получение своего профиля |
| Profile | `GET /users/:id/profile` | Получение чужого профиля |
| Feed | `GET /feed` | Получение реальных постов ленты |
| Feed | `POST /feed` | Создание поста |
| Feed | `PATCH /feed/:id` | Редактирование своего поста |
| Feed | `DELETE /feed/:id` | Удаление своего поста |
| Likes | `POST /feed/:id/like` | Лайк/дизлайк поста |
| Friends | `GET /users/:id/friends` | Список друзей пользователя |
| Messages | `GET /conversations` | Список диалогов |
| Messages | `GET /conversations/:id/messages` | Сообщения в чате |
| Messages | `POST /conversations/:id/messages` | Отправка сообщения |
| World | `GET /world` | Получение состояния мира |
| World | `POST /world/select` | Сохранение выбранного мира |

## 11. Реализация демоверсии

В рамках демоверсии реализуется ядро продукта, которое позволяет пройти основной пользовательский сценарий.

### Реализованное ядро

- базовая авторизация и регистрация;
- выбор мира;
- нижняя навигация приложения;
- экран мира;
- профиль пользователя;
- чужой профиль;
- список друзей;
- лента постов;
- создание поста с текстом и медиа;
- отображение постов в ленте и профиле;
- лайки;
- сообщения и переходы в чат;
- адаптация интерфейса под светлую и тёмную тему;
- glass-элементы интерфейса;
- минимальные пустые и ошибочные состояния.

### Что важно для демо

Главный акцент сделан на том, чтобы пользователь мог увидеть связность приложения: профиль, лента, посты, друзья, сообщения и мир не существуют отдельно, а образуют единую систему мотивации вокруг хобби.

## 12. Протокол первого end-to-end прогона

| № | Проверка | Результат | Проблема | Решение |
|---|----------|-----------|----------|---------|
| 1 | Запуск приложения | Выполнено | Нужно было проверить API-адрес для эмулятора | Для Android Emulator используется `10.0.2.2` |
| 2 | Вход пользователя | Выполнено | Возможны ошибки при неверных данных | Добавлены сообщения об ошибке |
| 3 | Выбор мира | Частично выполнено | Экран мира не всегда реагировал на тему | Экран переведён на общую тему |
| 4 | Открытие профиля | Выполнено | Иногда профиль не загружался | Добавлена более устойчивая загрузка |
| 5 | Создание поста | Выполнено | Медиа могло не отображаться | Добавлена поддержка разных форматов медиа |
| 6 | Лента | Выполнено | Появлялись тестовые/fake посты | Убран fallback на старые источники |
| 7 | Лайк | Выполнено | Лайк был плохо заметен | Добавлено мгновенное визуальное обновление |
| 8 | Сообщения | Выполнено | Текст в тёмной теме сливался | Улучшена контрастность |
| 9 | Чужой профиль | Выполнено | Нужно было сделать как свой профиль | Добавлен PublicProfileScreen в общем стиле |
| 10 | Друзья чужого профиля | Выполнено | В списке мог отображаться сам владелец | Добавлена фильтрация владельца профиля |

## 18. Ограничения текущей версии

| Ограничение | Причина |
|------------|---------|
| Мир пока не является полноценным 3D-пространством | Требуется отдельный этап разработки графики и логики |
| Строительство в мире реализовано не полностью | Нужно сначала стабилизировать core-сценарий |
| Достижения пока базовые | Требуется связать их с действиями пользователя |
| Push-уведомления не входят в демоверсию | Не критично для первого end-to-end сценария |
| Модерация жалоб ограничена | Нужна отдельная backend-логика |
| Медиа зависит от формата ответа backend | Требуется унифицировать контракт API |
| Некоторые состояния требуют тестирования на реальном устройстве | Эмулятор не всегда отражает поведение телефона |

## 20. Следующий фокус разработки: главный мир

После завершения базовой демоверсии следующим главным направлением становится развитие мира. Именно мир должен отличать **Hobby Worlds** от обычной социальной сети или трекера задач.

### Что нужно сделать в мире

- создать красивую визуальную сцену с островами;
- добавить дом пользователя;
- добавить объекты, которые открываются за прогресс;
- связать XP и достижения с изменениями мира;
- добавить цели и задания прямо в контекст мира;
- сделать анимации появления объектов;
- показать развитие мира как результат регулярного занятия хобби.

### Продуктовый смысл мира

Мир должен стать визуальным доказательством прогресса. Если пользователь занимается хобби, выполняет задания, публикует результаты и получает достижения, его мир должен становиться богаче, красивее и живее.
